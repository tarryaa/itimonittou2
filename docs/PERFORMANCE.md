# 動作軽量化の検証

v1.0.0と、3種類の表示テーマを選択できるv1.2.0を同じ計測スクリプトで比較しました。変更後は初期テーマ「栞（オリジナル）」（classic）です。教材JSON、問題ID、解答対応、既存の編集・学習記録は維持しています。

## 変更内容

- 全1,496問をDOMへ同時に描画する方式から、画面周辺の問題だけを描画する方式へ変更しました。全教材の連続スクロール、時代・章ラベル、図表・独立補足、全体に対する一括表示と絞り込みは維持します。
- スクロールで本文全体を再描画せず、閲覧位置と現在のセッション進捗だけを小さな保存データとして更新します。変更のない編集・間違い履歴を毎回複製・JSON化・書き込みしません。
- 赤字が最初から隠れている場合の不要な再描画と、閉じた空欄で発生していた大量のタイマーを取り除きました。
- 問題IDと相対位置による復元、長い問題の途中からの再開、画面幅変更時の位置補正、書き込み中断からの復元を維持します。

## 計測結果

Chromium、390×844px、CPU速度を4倍遅くした設定で、独立したブラウザを3回起動した中央値です。ローカルの本番ビルド配信を使い、ネットワーク速度は制限していません。Service Workerを無効化して描画・操作の負荷を比較しています。

| 項目 | 変更前（v1.0.0） | 変更後（v1.2.0・classic） | 変化 |
|---|---:|---:|---:|
| 最初の教材表示 | 7,254ms | 1,159ms | 84.0%短縮 |
| 初期DOM要素数 | 53,722 | 365 | 99.3%削減 |
| 同時に描画する問題数（初期） | 1,496問 | 6問 | 全教材は保持 |
| 赤字・解答の一括表示 | 1,480ms | 41ms | 97.2%短縮 |
| 一括非表示 | 2,116ms | 47ms | 97.8%短縮 |
| 間違い記録の追加 | 327ms | 47ms | 85.5%短縮 |
| スクロールのフレーム間隔・95パーセンタイル | 105.3ms | 22.8ms | 78.3%短縮 |
| 2.5秒のスクロールで50msを超えたフレーム間隔 | 12回 | 0回 | この計測条件で解消 |
| 初期JavaScriptヒープ | 約44.7MB | 約14.3MB | 68.0%削減 |

変更後のスクロール計測中に同時描画した問題は最大13問でした。変更後の3回の計測でJavaScript例外はありませんでした。操作時間はブラウザ内のクリックから表示確定と2回の描画フレームまでを計測し、Playwrightによる要素検索の時間を除いています。

これは比較用の開発環境での実測です。実機iPhoneの速度・タッチ操作・メモリ使用量を保証する数値ではありません。物理端末のSafariとホーム画面起動は別途確認が必要です。

## 再計測

```sh
npm run build
node scripts/measure-performance.mjs --cpu 4 --runs 3 --output docs/performance-after.json
```

スクリプトは本番ビルドをlocalhostの空きポートで一時配信し、終了時にブラウザと配信を停止します。別のビルドを計測する場合は `--dist /path/to/dist` を指定できます。ネットワーク上の学習記録やユーザーのブラウザ保存領域は使用しません。
